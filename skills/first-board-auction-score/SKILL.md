# 首板 ＋ 连板滚动跟踪（WorkBuddy 版）

**冻结模型本地推理：不训练、不调参、不改数、不联网。** 参数固化在 `assets/models.json`。

> ⛔ **产物形态：只交付 CSV 表格，不产 HTML。**
> 每日**唯一主交付** = `daily/{交易日}/first_board/连板跟踪_{交易日}.csv`。
> ⛔ 不产出、不依赖任何通达信侧产物 —— 无自定义公式（`.txt`）、无 `EXTERNVALUE`、无数值 ID 映射、无 `.blk`。

运行环境：Python 用 **venv 绝对路径**
`C:\Users\xc92\.workbuddy\binaries\python\envs\default\Scripts\python.exe`（本机 shell 缺 `ls`/`cat`/`dirname`）。
原始数据只读：`D:\OneDrive\Stock\短线数据采集\`、`D:\OneDrive\Stock\details\`。

## 一、核心：一张表活三步（用户 2026-09-24 定稿）

每张 `连板跟踪_{T}.csv` 覆盖**一个交易日**，被三个动作依次填写：

| 步 | 时机 | 命令 | 写入 |
|---|---|---|---|
| **① 建档** | T 日**收盘后** | `board_tracker.py init` | 建档块（当日首板 ＋ 上一表里**已晋级**的标的，身位+1） |
| **② 竞价** | T+1 **09:25–09:30** | `board_tracker.py snapshot` ＋ `auction` | 竞价块（实际开盘%/偏离/竞价评价/量能/1J2门） |
| **③ 复盘** | T+1 **收盘后** | `board_tracker.py eod` | 表现块（收盘涨幅/主力净额/是否晋级） |

**③ 里判为「晋级」的行 → 成为 T+1 那张表的建档输入** → 循环。

```
D 收盘     init(D)                                     → 连板跟踪_D.csv
D+1 09:25  snapshot + auction(连板跟踪_D)               → 补竞价块
D+1 收盘   eod(连板跟踪_D)                              → 补表现块
           score.py eod(D+1) → init(D+1, --prev 连板跟踪_D) → 连板跟踪_{D+1}.csv
D+2 09:25  snapshot + auction(连板跟踪_{D+1})           → …循环
```

### 目录约定（⛔ 看板按此路径读取）

**`daily/{交易日 T}/first_board/`** 存放 T 日全部产物：

| 路径 | 内容 | 交付 |
|---|---|---|
| **`连板跟踪_{T}.csv`** | ⭐ 滚动跟踪表 | **主交付** |
| `{T}_eod/` | 冻结快照：`eod_state.csv`／`manifest.json`／`排除明细.csv` | `排除明细.csv` 为次交付 |
| `fetch_{T+1}/` | `fetch_list.csv`／`fetch_protocol.md`／`quotes.json` | 内部 |
| `{T}_replay/` | 可选历史回放（补 09:25 窗口外的字段） | 内部 |

⛔ 不要新建 `daily/{尚未到来的日期}/`（会污染看板的「最新日期」扫描）。

## 二、日常命令

### ① T 日收盘后 —— 打分 ＋ 建档

```bat
:: 0) 先生成 2 板及以上要用的分数与基准（⛔ 三步必须严格串行，见 口径-看板与移动端.md）
::    build_sector_full  →  build_zt_quality  →  build_auction_baseline
python scripts\build_sector_full.py      --dates 2026-09-24
python scripts\build_zt_quality.py       --dates 2026-09-24 --top 0
python scripts\build_auction_baseline.py --date  2026-09-24

:: 1) 冻结收盘评分（产出 eod_state.csv，供 plan / init 消费）
python scripts\score.py eod --date {T} --evaluation-date {下一个交易日} --out daily\{T}\first_board\{T}_eod

:: 2) 建档（首张表不带 --prev；此后每天带上一张）
::    质量分默认读 daily\{T}\涨停质量.json（= eod 目录的上两级），缺失则「建档日质量分」留空并告警
python scripts\board_tracker.py init --date {T} --eod daily\{T}\first_board\{T}_eod ^
       --prev daily\{T-1}\first_board\连板跟踪_{T-1}.csv ^
       --out  daily\{T}\first_board\连板跟踪_{T}.csv

:: 3) 导出次日取数清单（默认全量）
python scripts\tdx_1j2.py plan --eod daily\{T}\first_board\{T}_eod --out daily\{T}\first_board\fetch_{T+1}
```

⛔ **下一个交易日不能猜**：先看 `{T}/snapshot.json` 的「上一交易日」核对，再查交易所节假日公告
（例：2026 中秋 9/25–9/27 休市 → 9/24 的评分日应填 **09-28**）。

### ② T+1 日 09:25 竞价 —— 评价

```bat
:: 1) 逐票 tdx_quotes(code, setcode, hasHQInfo=1) → 手工写 quotes.json（唯一允许的动作，见 fetch_protocol.md）
:: 2) 机械转录
python scripts\board_tracker.py snapshot --date {T+1} --quotes <fetch_{T+1}\quotes.json> --out <fetch_{T+1}\竞价快照.csv>
:: 3) 在跟踪表上直接评价
python scripts\board_tracker.py auction  --track daily\{T}\first_board\连板跟踪_{T}.csv --date {T+1} ^
       --snapshot <fetch_{T+1}\竞价快照.csv> --baseline daily\{T}\竞价预期基准.json
```

⛔ **时间窗铁律**：`HQInfo.Amount` 只有 **09:25–09:30** 才是**竞价成交额**；09:30 后是全天累计额，
会污染竞昨比与量能门。⛔ **全量取数只取 `HQInfo`（`hasHQInfo=1`），禁开 `hasCalcInfo`**。
⛔ 语言模型在②里**零决策权**：不挑票、不排序、不改数、不补缺失值。

**② 缺席时的回放回填（details 口径，2026-09-28 实证）**：若竞价节点未产出 quotes.json，
收盘后可用 `D:\OneDrive\Stock\details\全部Ａ股{D}.xlsx` 回放——列 `今开`(10)＝竞价开盘价、
`开盘%`(16)、`开盘金额`(17, **单位万元**，×10000 转元写入 amount)、`竞价昨比`(19)；
`prev_close` 用跟踪表内 `建档日收盘价`（建档日=涨停收盘=昨收，精确，禁用 open/(1+pct%) 反推）；
`time` 如实写实际采集时刻（如 092600）。整表可 0 缺失回填，且量能标签可正常核验；
此回放**仅作补救**，优先仍为 09:25 窗口实时采集。

### ③ T+1 日收盘后 —— 复盘 ＋ 滚动

```bat
python scripts\board_tracker.py eod --track daily\{T}\first_board\连板跟踪_{T}.csv --date {T+1}
:: 然后重复①的三步，生成 连板跟踪_{T+1}.csv
```

## 三、跟踪表列义（47 列，**按「关键信息前置」排序**）

| 段 | 列 |

**表内标的跟到断板**：只要一直涨停晋级，就带着「身位+1」一路滚进下一张表；未晋级即自然退出。
身位列如实标注实际连板数（首板／2板／3板／高位板）。

⚠️ **写入时目标被 Excel/预览占用**（Windows 锁）→ 脚本自动降级另存 `<名>.new.csv` 并显式告警，
**不会静默失败**；关闭占用后重跑即可覆盖。

## 四、打分与竞价评价：首板 vs 2 板及以上

**两者都有分数、也都能做竞价三档，但用的是两把不同的尺子 —— 不可比大小。**

| 项 | **首板** | **2 板及以上** |
|---|---|---|
| **分数** | `首板晋级分`＝100×六因子逻辑回归概率（**晋级概率**，典型 4–55） | `建档日质量分`＝五维绝对尺度（**封板质量**，典型 38–93）<br>来源 `build_zt_quality.py` → `daily/{T}/涨停质量.json`，**全市场通用、跨身位可比** |
| **分数的含义** | 次日一进二的**概率** | 封板牢不牢（时间25／牢固度25／大单流入20／板块共振20／量能10） |
| **竞价三档** | 1J2 冻结模型：`偏离 = 实际开盘% − 预期开盘%`，与 `residual_low/high` 比较 | 质量分档基准：`daily/{T}/竞价预期基准.json` 的逐票 `不及_阈值`／`超_阈值` |
| **超预期分 / 量能标签** | 有 | 无（留空 / `（无基准）`） |
| **专属门** | `1J2门` 四门 | 无 |

⛔ **2 板及以上没有专属「晋级概率」模型**（1J2 模型按构造只预测首板→1进2）。
不要用质量分去替代晋级概率、也不要用首板晋级分给 2 板排序 —— 两者的量纲与含义都不同。
**要真做 2 板的晋级概率模型属重训，非日常动作。**

**为什么质量分对 2 板同样有效**：它是**绝对尺度**，09:25 一字板永远高分，跨身位可比。
实证 20260924：**2 板均分 67.8 > 首板均分 62.8**（对照 09-17 高位板 38.8 vs 首板 64.5）
—— 身位高低与封板质量不呈单调关系，这正是「质量 ≠ 风险」的由来。

## 五、竞价三档的两套口径（⛔ 不可混用，表内 `竞价基准口径` 列已标注）

| 身位 | 口径 | 基准来源 | 三档判据 |
|---|---|---|---|
| **首板** | **1J2 冻结模型** | `assets/models.json`：`预期开盘%` ＋ `residual_low/high` | `偏离 < −3.2959383007202194` 不及预期；`> +2.5239430446936617` 超预期；其间符合预期 |
| **2 板及以上** | **质量分档基准** | `daily/{T}/竞价预期基准.json`（`build_auction_baseline.py` 产出，逐票 `不及_阈值`／`超_阈值`） | 实际开盘% 与两阈值比较 |

- 基准文件缺失 → `竞价基准口径=基准缺失`，三档**留空**，**禁拍阈值**。
- 生成顺序（⛔ 必须严格串行）：`build_sector_full.py` → `build_zt_quality.py` → `build_auction_baseline.py`。

### `1J2门` 列（仅首板）
四条实质门全部满足才写「通过」，否则写「未通过：原因」——
**非涨停竞价**（开盘 < 涨停价×0.995）｜**旧涨幅门**（2% ≤ 实际开盘% ≤ 8.5%）｜
**旧竞昨比门**（3% ≤ 竞昨比 ≤ 90%）｜**预期门**（偏离 ≥ 残差下界）。
（取数范围门自 2026-09-24 起默认关闭 —— 改为全量取数。）

## 五、实测基线与用法铁律

**20260923（n=35，退潮日）**：晋级率 **8.6%**、收盘中位 **−2.56%**、收红 37.1%；
Spearman(首板分, 实际开盘%) **+0.256**、~超预期分 **−0.204**、~T日收盘 **−0.009**、~是否晋级 **−0.263**；
「超预期」组晋级率 28.6% vs 「符合预期」组 3.7%；**前20% 与 20–40% 组晋级率均为 0%**。

**20260924（n=32，修复日）**：晋级率 **25.0%**、收盘均值 +0.70%、收红 50.0%；
Spearman：实际开盘%~收盘 **+0.326**、首板分~收盘 **+0.319**、~晋级 **+0.289**（**符号全部翻正**）。
⭐ **两头是机会、中间最差**：「超预期」组晋级率 **80%**（4/5）、「不及预期」组 **100%**（2/2）、
「符合预期」组仅 **8.0%**（2/25）→ 不一味排除「不及预期」，退潮末期低开反包是常见形态。

⭐ **用法铁律**
1. **首板晋级分不作买入排序** —— 两日符号相反、日均近零。只用于**建档排序 + 前20%标注**；
   真正决定候选的是 T 日竞价四条门（`1J2门` 列）。
2. **`竞价超预期分` 有系统性偏差** —— 预期开盘% 与首板分同源，分数高则预期被抬高 → 对高分标的偏低。
   排序以**实际开盘% 绝对档位**为准。
3. **全量取数**（`--top-pct` 默认 1.0）：09-23 实测 7 只「超预期」中 6 只排在前 20% 之外；
   09-24 实测 **4 只候选全部排在前 50% 之外** → 取前段会系统性漏掉。
4. **单日不可下结论**：以上仅 2 日样本，⛔ **禁止据此调 `models.json`**，须逐日累积。

**范围声明**：普通 10% 主板首板；研究数据截至 20260921；未独立验证新阶段收益。
无成交、T+1 退出或收益承诺。**所有输出为研究排序，不构成投资建议。**
